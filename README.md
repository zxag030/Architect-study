## 교재 PDF (사용자 기기에만 저장)

설정 또는 문제의 **교재 보기**에서 PDF를 선택하면 동일 사이트의 IndexedDB에 저장됩니다. 이후 같은 브라우저에서 자동 연결됩니다. 인쇄 80쪽이 PDF 84페이지라면 **페이지 오프셋**에 `4`를 입력하세요. 음수도 가능합니다. 뷰어의 페이지 이동 입력은 PDF 실제 페이지 번호입니다.

PDF는 GitHub나 외부 서버로 전송되지 않으며 JSON 학습 백업에도 포함되지 않습니다. 브라우저 데이터 삭제, 비공개 모드, 저장 공간 정리로 파일이 사라지면 다시 선택하세요. 저장 실패 시에도 현재 탭에서는 열 수 있으며 재선택 안내를 표시합니다. PDF 교체는 기존 학습 기록에 영향을 주지 않습니다. 암호화되거나 손상된 PDF는 잠금 해제/복구한 파일을 선택하세요.

PDF.js와 worker, CMaps, 기본 글꼴은 `vendor/pdfjs`에서 같은 사이트 경로로 제공됩니다. `file://`로 직접 여는 대신 GitHub Pages 또는 정적 HTTP 서버를 사용하세요.

```sh
python3 -m http.server 8000
```

## 테스트

Node.js와 Playwright가 필요합니다. Playwright를 별도 경로에 설치하면 앱의 의존성 없이 테스트할 수 있습니다.

```sh
npm install --prefix /tmp/architect-tests playwright@1.62.1
export NODE_PATH=/tmp/architect-tests/node_modules
export PLAYWRIGHT_BROWSERS_PATH=/tmp/architect-browsers
node /tmp/architect-tests/node_modules/playwright/cli.js install chromium webkit
export CHROMIUM_PATH=$(node -e "console.log(require('playwright').chromium.executablePath())")
node tests/daily-progress.cjs
node tests/textbook.cjs
TEST_WEBKIT=1 node tests/textbook.cjs
node tests/pdf-navigation.cjs
TEST_WEBKIT=1 node tests/pdf-navigation.cjs
```

테스트 PDF는 테스트가 메모리에서 생성하는 도형 2페이지이며 교재 원문을 포함하지 않습니다.


PDF 이동 회귀 테스트는 서로 다른 색의 3페이지 PDF로 캔버스 픽셀을 확인합니다. 실제 터치 이벤트로 번호 입력 직후 이전/다음 이동, 서로 다른 문제의 출처 페이지, 재접속, 라이브러리/worker 로딩 지연·실패와 진행 중 렌더 취소를 검사합니다. Playwright WebKit 실행은 실제 iPad Safari 기기 검증을 대신하지 않습니다.

### iPad Safari에서 확인하기

1. 교재 PDF를 선택하고 문제의 **교재 보기**를 누릅니다. 상단 전체 페이지 수가 표시될 때까지 기다립니다.
2. 인쇄 쪽수와 PDF 실제 페이지가 다르면 오프셋을 설정합니다. 첫 페이지로 자동 대체하지 않으며 범위를 벗어나면 계산 결과와 허용 범위를 표시합니다.
3. 번호 입력 후 이전/다음 버튼을 바로 터치하고 실제 내용이 바뀌는지 확인합니다. 서로 다른 쪽수의 두 문제에서도 확인합니다.
4. 뷰어를 닫아 작성 답안이 남아 있는지, 사이트를 다시 열어 저장된 PDF가 연결되고 페이지 이동이 되는지 확인합니다.

표시 실패 시 문서/worker 로드, 페이지 읽기, 렌더링 중 어느 단계에서 발생했는지 오류 이름과 메시지를 표시합니다. **표시 다시 시도** 또는 PDF 다시 선택을 사용할 수 있습니다. PDF.js와 worker는 `textbook.js` 위치를 기준으로 같은 사이트에서 불러옵니다.


## 신규 학습과 독립 복습

신규 학습은 기존 **따라 쓰기 10회 → 핵심 빈칸 통과 → 백지서술 연습 → 학습 완료**를 유지합니다. 새 개념은 평가 대기(unrated)로 저장하며, 기존 분류가 있는 개념은 재학습해도 숙지도를 임의로 바꾸지 않습니다.

복습 시작 화면에서 다음 항목을 선택합니다.

- 방식: **3회 따라 쓰기 / 핵심 빈칸 / 백지서술** 중 한 가지. 다른 두 방식을 연달아 할 필요가 없습니다.
- 문제 수: 10개 단위 또는 전체. 남은 대상이 적으면 가능한 수만 출제합니다.
- 대상: 부족한 문제 우선 / 오늘 복습 예정 / 전체 문제. 포함할 등급을 각각 선택할 수 있습니다.
- 순서: 부족 우선은 부족한 것 → 더 공부할 것 → 완벽하게 외운 것 순이며 평가 대기·미학습은 뒤에 포함합니다. 무작위 순서도 선택할 수 있습니다.

따라 쓰기는 정확하게 3회를 입력한 뒤 완료합니다. 빈칸은 일부 글자 힌트, 정답 보기, 정답 확인, 다시 풀기를 제공합니다. 정답 보기만으로 완료하거나 숙지도를 올리지 않습니다. 다시 풀기는 모든 답·정답 노출·힌트·판정·통과 상태를 초기화합니다. 따라 쓰기/빈칸을 마쳐도 기존 숙지도는 유지합니다.

백지서술의 키워드·분량 자동 평가는 참고 정보이며 AI 의미 채점이 아닙니다. **완벽하게 외운 것 / 더 공부할 것 / 부족한 것** 중 사용자가 최종 확정해야 저장됩니다. 기본 간격은 4/2/1일입니다. 서로 다른 날짜에 완벽한 회상을 연속 확정하면 4→8→12→16일로 조정하며, 다른 등급으로 바꾸면 초기화합니다. 같은 날 반복으로 간격을 늘리지 않습니다. 화면에 제시되는 등급은 사용자가 언제든 임의 복습할 수 있습니다.

오늘 복습 예정에서는 이미 오늘 완료한 문제를 빼지만, 전체/등급별 임의 연습은 다시 선택할 수 있습니다. 같은 문제를 여러 모드로 연습해도 **오늘 복습 완료 문제 수는 한 번만 증가**합니다. 연습 횟수와 상세 이력은 각각 남습니다. 기존 복습 누적 카운터는 보존하며 이 버전부터 reviewCount는 문제별 하루 첫 완료에만 증가합니다.

미학습 문제를 복습하거나 등급을 정하더라도 신규 학습 완료로 간주하지 않습니다. learningCompleted=false가 남아 신규 목표에 계속 포함되며, 신규 1~3단계를 완료할 때만 신규 완료가 됩니다.

## 시험 계획과 대시보드

시험일은 **2026-11-07**, 신규 학습 마감은 **2026-11-03**입니다. 권장량은 (남은 미학습 + 오늘 완료한 신규 문제 수) / 마감까지 남은 날짜(오늘 포함)를 올림하여 계산합니다. 신규 문제를 완료할 때 같은 날 목표가 줄어들지 않게 하는 계산입니다. 직접 목표를 입력한 뒤 **목표 적용**, 또는 **권장 목표 사용**으로 되돌릴 수 있습니다.

11월 4~6일에는 신규 자동 목표가 0이 되고 대시보드는 전체 복습 중심으로 표시합니다. 기존 목표 설정을 삭제하지 않습니다. 문제은행의 신규 학습 버튼으로 필요한 개별 학습은 계속할 수 있습니다. 시험 당일 이후에도 자동 신규 목표는 0이며 개별 학습은 가능합니다.

대시보드는 신규 목표/완료/남은 목표 수, 미학습 수, 오늘 복습 완료, 등급별 문제 수, 시험 D-day를 구분합니다. 기존 PLAN과 날짜별 진도는 펼쳐 보기로 보존합니다.

## 백업 복원과 기기 병합

기존 v2 저장 키와 cards/progress/dailyCompletions/reviewDays를 유지하고 reviewHistory, backupConflicts 및 선택적 메타데이터를 추가합니다. 이전 데이터와 백업을 자동으로 초기화하거나 과거 숙지도를 추정 변경하지 않습니다. 기존 누적값을 상세 이력으로 임의 생성하지 않습니다.

**백업 복원·기기 병합은 항상 기존 자료와 병합**합니다.

- 날짜별 완료 ID와 이벤트 ID를 합집합으로 합치며 같은 파일을 반복해서 가져와도 중복 증가하지 않습니다.
- 명시적 날짜/시간이 더 최근인 진도를 사용하고, 동률·불명확한 경우 현재 값을 유지합니다. 서로 다른 원본 문제/진도/설정 등은 양쪽 전체 값을 backupConflicts에 보관합니다. 충돌 수는 설정 화면에 표시하며 내보내기에 원본들이 포함됩니다.
- 이전 누적 횟수는 최대값을 보존하고 확인 가능한 고유 이력으로만 안전한 하한을 보정합니다. 상세 내역 없는 과거 횟수를 추측해 합산하지 않습니다.
- 새 상세 복습 이력은 문제·날짜·방식·최종 숙지도·다음 복습일을 기록합니다. 화면에는 최근 30건, JSON에는 전체 이력이 포함됩니다.
- 가져오기 직전 사본을 별도 로컬 키에 저장하며 **가져오기 전 사본 저장**으로 내려받을 수 있습니다. 검증/공간 부족으로 병합 저장이 실패하면 기존 활성 데이터는 유지됩니다.
- 현재 문제 또는 진도를 충돌 이전 값으로 되돌려야 한다면 사본과 backupConflicts를 확인하여 원하는 값을 검토해야 합니다. 병합은 현재 기록을 삭제하는 과거 시점 덮어쓰기 기능이 아닙니다.

PDF 파일은 백업에 포함하지 않으며 기존 IndexedDB 교재 저장소는 변경하지 않습니다.

## iPad 한글 입력과 실제 기기 확인

study-input.js에서 학습 입력 이벤트를 한 번만 처리합니다. 빈칸의 인라인 oninput은 없습니다. 한 번에 한 빈칸만 편집 가능하게 하며, 이전 한글 조합이 끝나기 전 다른 칸은 readonly로 보호합니다. 전환 안내가 뜨면 키보드 **완료** 후 그 칸을 다시 눌러주세요. 프로그램이 강제로 blur/focus하거나 조합 중 값을 덮어쓰지 않습니다. 힌트는 입력 노드를 교체하지 않으며 다시 풀기는 조합 확정 뒤 새 시도로 초기화합니다.

실제 iPad Safari/OS 한글 키보드는 자동화로 검증하지 못했습니다. 다음 절차로 확인할 수 있습니다.

1. 핵심 빈칸 모드를 선택하고 서로 다른 칸에 가설지지체 → 작업공간 → 태핑을 입력합니다. 실제 정답과 다른 칸의 태핑이 오답 처리되는 것은 정상입니다.
2. 조합 도중 빠르게 다른 칸을 누르고 안내에 따라 키보드 완료/재터치합니다. 이전 글자가 다른 칸에 복사되지 않는지 확인하고 삭제·재입력합니다.
3. 힌트/정답 보기만으로 완료 수와 숙지도가 바뀌지 않는지, 오답 후 다시 풀기로 값·판정·노출이 모두 지워지는지 확인합니다.
4. 한글 조합 중 정답 확인/복습 완료/다음 단계를 누르고 네이티브 입력 확정 후 최신 값으로 처리되는지 확인합니다.
5. PDF를 열고 닫은 뒤 답안, 재접속 후 교재 자동 연결, JSON 병합 후 기존 기록을 확인합니다.

문제가 남으면 **입력 진단 저장**으로 최대 160개의 이벤트 종류·필드 ID·입력 종류·조합 단계·차단 여부·시간만 기기에 저장할 수 있습니다. 답안 문자열과 교재 내용은 포함하거나 전송하지 않습니다.
