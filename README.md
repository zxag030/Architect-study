## 교재 PDF (사용자 기기에만 저장)

설정 또는 문제의 **교재 보기**에서 PDF를 선택하면 동일 사이트의 IndexedDB에 저장됩니다. 이후 같은 브라우저에서 자동 연결됩니다. 인쇄 80쪽이 PDF 84페이지라면 **페이지 오프셋**에 `4`를 입력하세요. 음수도 가능합니다. 뷰어의 페이지 이동 입력은 PDF 실제 페이지 번호입니다.

PDF는 GitHub나 외부 서버로 전송되지 않으며 JSON 학습 백업에도 포함되지 않습니다. 브라우저 데이터 삭제, 비공개 모드, 저장 공간 정리로 파일이 사라지면 다시 선택하세요. 저장 실패 시에도 현재 탭에서는 열 수 있으며 재선택 안내를 표시합니다. PDF 교체는 기존 학습 기록에 영향을 주지 않습니다. 암호화되거나 손상된 PDF는 잠금 해제/복구한 파일을 선택하세요.

PDF.js와 worker, CMaps, 기본 글꼴은 `vendor/pdfjs`에서 같은 사이트 경로로 제공됩니다. `file://`로 직접 여는 대신 GitHub Pages 또는 정적 HTTP 서버를 사용하세요.

```sh
python3 -m http.server 8000
```

## 테스트

Node.js와 Playwright가 필요합니다. Playwright를 별도 경로에 설치하면 앱의 의존성 없이 테스트할 수 있습니다.

```sh
npm install --prefix /tmp/architect-tests playwright@1.62.1
export NODE_PATH=/tmp/architect-tests/node_modules
export PLAYWRIGHT_BROWSERS_PATH=/tmp/architect-browsers
node /tmp/architect-tests/node_modules/playwright/cli.js install chromium webkit
export CHROMIUM_PATH=$(node -e "console.log(require('playwright').chromium.executablePath())")
node tests/daily-progress.cjs
node tests/textbook.cjs
TEST_WEBKIT=1 node tests/textbook.cjs
node tests/pdf-navigation.cjs
TEST_WEBKIT=1 node tests/pdf-navigation.cjs
```

테스트 PDF는 테스트가 메모리에서 생성하는 도형 2페이지이며 교재 원문을 포함하지 않습니다.


PDF 이동 회귀 테스트는 서로 다른 색의 3페이지 PDF로 캔버스 픽셀을 확인합니다. 실제 터치 이벤트로 번호 입력 직후 이전/다음 이동, 서로 다른 문제의 출처 페이지, 재접속, 라이브러리/worker 로딩 지연·실패와 진행 중 렌더 취소를 검사합니다. Playwright WebKit 실행은 실제 iPad Safari 기기 검증을 대신하지 않습니다.

### iPad Safari에서 확인하기

1. 교재 PDF를 선택하고 문제의 **교재 보기**를 누릅니다. 상단 전체 페이지 수가 표시될 때까지 기다립니다.
2. 인쇄 쪽수와 PDF 실제 페이지가 다르면 오프셋을 설정합니다. 첫 페이지로 자동 대체하지 않으며 범위를 벗어나면 계산 결과와 허용 범위를 표시합니다.
3. 번호 입력 후 이전/다음 버튼을 바로 터치하고 실제 내용이 바뀌는지 확인합니다. 서로 다른 쪽수의 두 문제에서도 확인합니다.
4. 뷰어를 닫아 작성 답안이 남아 있는지, 사이트를 다시 열어 저장된 PDF가 연결되고 페이지 이동이 되는지 확인합니다.

표시 실패 시 문서/worker 로드, 페이지 읽기, 렌더링 중 어느 단계에서 발생했는지 오류 이름과 메시지를 표시합니다. **표시 다시 시도** 또는 PDF 다시 선택을 사용할 수 있습니다. PDF.js와 worker는 `textbook.js` 위치를 기준으로 같은 사이트에서 불러옵니다.


## 신규 학습과 독립 복습

신규 학습은 기존 **따라 쓰기 10회 → 핵심 빈칸 통과 → 백지서술 연습 → 학습 완료**를 유지합니다. 새 개념은 평가 대기(unrated)로 저장하며, 기존 분류가 있는 개념은 재학습해도 숙지도를 임의로 바꾸지 않습니다.

복습 시작 화면에서 다음 항목을 선택합니다.

- 방식: **3회 따라 쓰기 / 핵심 빈칸 / 백지서술** 중 한 가지. 다른 두 방식을 연달아 할 필요가 없습니다.
- 문제 수: 10개 단위 또는 전체. 남은 대상이 적으면 가능한 수만 출제합니다.
- 대상: 부족한 문제 우선 / 오늘 복습 예정 / 전체 문제. 포함할 등급을 각각 선택할 수 있습니다.
- 순서: 부족 우선은 부족한 것 → 더 공부할 것 → 완벽하게 외운 것 순이며 평가 대기·미학습은 뒤에 포함합니다. 무작위 순서도 선택할 수 있습니다.

신규 따라 쓰기는 **한 화면의 10개 입력칸**, 복습 따라 쓰기는 **한 화면의 3개 입력칸**을 세로로 배치합니다. 문제와 정답을 위에 표시하며 정답 보기/가리기를 제공합니다. 각 칸은 여러 줄을 작성할 수 있고, 입력 중 같은 DOM 노드를 유지합니다. 작성률은 공백이 아닌 칸의 비율이며 정답 일치 판정과 별도로 표시합니다. **전체 정답 확인**에서 모든 칸이 정답과 일치해야 다음 단계 또는 복습 완료가 가능합니다. NFC 한글 표현과 띄어쓰기·줄바꿈만 정규화하고 숫자·부호·기호·내용 누락은 통과시키지 않습니다. 빈칸은 일부 글자 힌트, 정답 보기, 정답 확인, 다시 풀기를 제공합니다. 정답 보기만으로 완료하거나 숙지도를 올리지 않습니다. 다시 풀기는 현재 화면의 모든 답·정답 노출·힌트·판정·통과 상태를 초기화합니다. 해당 문제에서 힌트나 정답을 한 번이라도 사용했는지는 별도로 유지해 복습 이력의 hintUsed/answerViewed에 기록합니다. 따라 쓰기/빈칸을 마쳐도 기존 숙지도는 유지합니다.

백지서술의 키워드·분량 자동 평가는 참고 정보이며 AI 의미 채점이 아닙니다. **완벽하게 외운 것 / 더 공부할 것 / 부족한 것** 중 사용자가 최종 확정해야 저장됩니다. 기본 간격은 4/2/1일입니다. 서로 다른 날짜에 완벽한 회상을 연속 확정하면 4→8→12→16일로 조정하며, 다른 등급으로 바꾸면 초기화합니다. 같은 날 반복으로 간격을 늘리지 않습니다. 화면에 제시되는 등급은 사용자가 언제든 임의 복습할 수 있습니다. 정답 비교 뒤 답안을 수정하면 이전 비교·평가 화면을 숨기고 다시 비교해야 최종 등급을 저장할 수 있습니다.

오늘 복습 예정에서는 이미 오늘 완료한 문제를 빼지만, 전체/등급별 임의 연습은 다시 선택할 수 있습니다. 같은 문제를 여러 모드로 연습해도 **오늘 복습 완료 문제 수는 한 번만 증가**합니다. 연습 횟수와 상세 이력은 각각 남습니다. 기존 복습 누적 카운터는 보존하며 이 버전부터 reviewCount는 문제별 하루 첫 완료에만 증가합니다.

미학습 문제를 복습하거나 등급을 정하더라도 신규 학습 완료로 간주하지 않습니다. learningCompleted=false가 남아 신규 목표에 계속 포함되며, 신규 1~3단계를 완료할 때만 신규 완료가 됩니다.

## 시험 계획과 대시보드

시험일은 **2026-11-07**, 신규 학습 마감은 **2026-11-03**입니다. 권장량은 (남은 미학습 + 오늘 완료한 신규 문제 수) / 마감까지 남은 날짜(오늘 포함)를 올림하여 계산합니다. 신규 문제를 완료할 때 같은 날 목표가 줄어들지 않게 하는 계산입니다. 직접 목표를 입력한 뒤 **목표 적용**, 또는 **권장 목표 사용**으로 되돌릴 수 있습니다.

11월 4~6일에는 신규 자동 목표가 0이 되고 대시보드는 전체 복습 중심으로 표시합니다. 기존 목표 설정을 삭제하지 않습니다. 문제은행의 신규 학습 버튼으로 필요한 개별 학습은 계속할 수 있습니다. 시험 당일 이후에도 자동 신규 목표는 0이며 개별 학습은 가능합니다.

대시보드는 신규 목표/완료/남은 목표 수, 미학습 수, 오늘 복습 완료, 등급별 문제 수, 시험 D-day를 구분합니다. 기존 PLAN과 날짜별 진도는 펼쳐 보기로 보존합니다.

## 복습 이어하기

복습 문제 ID와 순서, 선택한 한 가지 모드, 현재 위치, 완료 ID와 이벤트 ID, 문제별 입력 초안과 힌트·정답 사용 여부를 `reviewSession`에 자동 저장합니다. 타이핑 후 잠시 멈추면 저장하며, 화면을 닫거나 다른 앱으로 전환할 때도 현재 DOM의 최신 조합 중 텍스트를 읽어 초안으로 보관합니다. 조합을 강제로 확정하거나 입력칸 값을 변경하지 않습니다.

- 새로고침 또는 같은 브라우저 재접속 후 **진행 중 복습 이어하기 → 이어하기**를 선택합니다. 자동으로 시험을 시작하지 않습니다.
- **저장하고 나가기**와 메뉴 이동은 초안을 유지합니다. **새로 시작 / 복습 종료**는 확인 후 활성 복습을 닫으며 원본 초안은 `reviewSessionArchive`에 보관합니다.
- 복습 완료 이력과 다음 문제 위치를 한 번에 저장합니다. 이미 저장한 이벤트 ID를 다시 만나면 완료 수를 중복 증가시키지 않습니다.
- 문제은행에서 정답/빈칸을 수정한 경우 이전 초안 사본을 보관하고 판정을 초기화합니다. 다른 문제의 답을 다음 문제에 재사용하지 않습니다.
- 저장 실패 시 화면의 입력값과 기존 저장 기록을 유지하며 안내합니다. 복습 화면의 **초안 JSON 백업**은 현재 화면의 최신 복습 초안도 포함합니다.
- 다른 탭에서 같은 사이트의 기록을 변경하면 현재 탭의 자동 저장을 중단해 덮어쓰기를 방지합니다. 현재 초안을 JSON으로 백업하고 새로고침한 뒤 기록 병합으로 합치세요.

신규 학습 완료 기록과 복습 완료 통계는 별도입니다. 이 이어하기 기능은 복습 세션을 대상으로 하며, PDF 파일은 초안이나 백업에 넣지 않습니다.

## 백업 복원과 기기 병합

기존 v2 저장 키와 cards/progress/dailyCompletions/reviewDays를 유지하고 reviewHistory, backupConflicts, reviewSession, reviewSessionArchive 및 선택적 메타데이터를 추가합니다. 이전 데이터와 백업을 자동 초기화하거나 과거 숙지도를 추정 변경하지 않습니다. 기존 누적값을 상세 이력으로 임의 생성하지 않습니다.

설정에 **백업 가져오기**와 별도 **기록 병합**을 제공합니다. 두 경로 모두 기존 기록을 보존하는 병합이며, 적용 전에 문제 수·이력 수·충돌 원본·실제로 사용할 값을 미리 보여줍니다. **취소**하면 기록을 변경하지 않습니다.

- **병합 전 현재 원본 백업** 또는 미리보기의 **적용 전 현재 원본 백업**으로 원본 파일을 먼저 저장할 수 있습니다.
- 날짜별 완료 ID와 이벤트 ID는 합집합으로 합치며 같은 파일을 반복해서 가져와도 중복 증가하지 않습니다. 동일 카드 ID는 한 문제로 합칩니다.
- 숙지도·복습 예정일은 명시적 날짜/시간이 더 최근인 진도를 사용하며, 동률·불명확한 경우 현재 값을 유지합니다. 서로 다른 원본 문제/진도/설정 등은 양쪽 전체 값을 backupConflicts에 보관하고 **보존된 충돌 확인**에서 펼쳐 비교할 수 있습니다.
- 이전 누적 횟수는 최대값을 보존하고 확인 가능한 고유 이력으로만 안전한 하한을 보정합니다. 상세 내역 없는 과거 횟수를 추측해 합산하지 않습니다.
- 기기별 복습 세션의 순서·모드·초안이 다르면 **어느 세션으로 이어할지 직접 선택**해야 적용할 수 있습니다. 각 필드를 섞거나 자동 덮어쓰지 않으며, 선택하지 않은 원본도 reviewSessionArchive와 전체 백업에 남깁니다.
- 새 상세 복습 이력은 문제·날짜·방식·최종 숙지도·다음 복습일·힌트/정답 사용을 기록합니다. 화면에는 최근 30건, JSON에는 전체 이력이 포함됩니다.
- 적용 직전 사본을 별도 로컬 키에 저장하며 **가져오기 전 사본 저장**으로 내려받을 수 있습니다. 검증/공간 부족으로 저장이 실패하면 기존 활성 데이터는 유지되고 미리보기에서 재시도할 수 있습니다.

PDF 파일은 백업에 포함하지 않으며 기존 IndexedDB 교재 저장소는 변경하지 않습니다. 교재 자동 복원 완료/실패 안내는 전체 화면 대신 관련 안내만 갱신해, 누르는 중인 이어하기 버튼과 학습 입력칸을 교체하지 않습니다.

## iPad 한글 입력과 실제 기기 확인

study-input.js에서 학습 입력 이벤트를 한 번만 처리합니다. 빈칸의 인라인 oninput은 없습니다. 한 번에 한 빈칸/따라 쓰기 칸만 편집 가능하게 하며, 이전 한글 조합이 끝나기 전 다른 칸은 readonly로 보호합니다. 전환 안내가 뜨면 키보드 **완료** 후 그 칸을 다시 눌러주세요. 프로그램이 강제로 blur/focus하거나 조합 중 값을 덮어쓰지 않습니다. 힌트는 입력 노드를 교체하지 않으며 다시 풀기는 조합 확정 뒤 새 시도로 초기화합니다.

실제 iPad Safari/OS 한글 키보드는 자동화로 검증하지 못했습니다. 다음 절차로 확인할 수 있습니다.

1. 신규 학습 10개 칸과 복습 3개 칸에 긴 정답을 입력하고 정답 가리기·전체 확인을 사용합니다. 빠르게 칸을 옮겨도 기존 글자가 다음 칸으로 복사되지 않는지 확인합니다.
2. 핵심 빈칸 모드를 선택하고 서로 다른 칸에 가설지지체 → 작업공간 → 태핑을 입력합니다. 실제 정답과 다른 칸의 태핑이 오답 처리되는 것은 정상입니다.
3. 조합 도중 빠르게 다른 칸을 누르고 안내에 따라 키보드 완료/재터치합니다. 이전 글자가 다른 칸에 복사되지 않는지 확인하고 삭제·재입력합니다.
4. 힌트/정답 보기만으로 완료 수와 숙지도가 바뀌지 않는지, 오답 후 다시 풀기로 값·판정·노출이 모두 지워지는지 확인합니다.
5. 한글 조합 중 정답 확인/복습 완료/다음 단계를 누르고 네이티브 입력 확정 후 최신 값으로 처리되는지 확인합니다.
6. 복습 답안 작성 중 새로고침/탭 종료 후 다시 열어 **이어하기**에서 순서·모드·입력 초안·완료 위치가 남는지 확인합니다.
7. PDF를 열고 닫은 뒤 답안, 재접속 후 교재 자동 연결, JSON 병합 후 기존 기록을 확인합니다.

문제가 남으면 **입력 진단 저장**으로 최대 160개의 이벤트 종류·필드 ID·입력 종류·조합 단계·차단 여부·시간만 기기에 저장할 수 있습니다. 답안 문자열과 교재 내용은 포함하거나 전송하지 않습니다.
